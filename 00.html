Lab 8.2 – EIGRP Unequal Cost Load Balancing

الهدف الأساسي: فهم وتطبيق خاصية Unequal Cost Load Balancing باستخدام أمر variance في EIGRP، وكيف يختار الـ Router أكثر من مسار (حتى لو الـ Metric مختلف) بشرط الـ Feasibility Condition.

1. Lab Overview

الهدف من اللاب ⭐

في EIGRP العادي (Equal Cost) الـ Router بياخد المسارات اللي ليها نفس الـ Metric بالظبط. لكن لو عايز يستخدم مسارات أبطأ كمان (Unequal Cost) علشان يستغل الـ Bandwidth المتاح، بنستخدم أمر variance.

المشكلة اللي بيحلها:
لو عندك مسار سريع ومسار أبطأ شوية، EIGRP بياخد السريع بس ويسيب الأبطأ. الـ variance بيسمحله يستخدم الاتنين مع بعض (Load Balancing) بشرطين مهمين جداً.

الشروط الأساسية لـ Unequal Cost Load Balancing:

  1. Feasibility Condition: الـ Advertised Distance (AD) بتاع المسار الأبطأ لازم يكون أقل من الـ Feasible Distance (FD) بتاع أفضل مسار.
  2. Variance: الـ Metric بتاع المسار الأبطأ لازم يكون ≤ (Variance × Best Metric).

الـ Topology

R1 (Serial1/0) ────── 10.0.0.0/30 ────── (Serial1/0) R2
│ │
│ │ Fa0/0
│ │ 12.0.0.0/24
│ │
(Serial1/1) (Fa0/0)
11.0.0.0/30 R3
│ │
└──────────────────── Serial1/1 ───────────────┘

الـ Destination اللي هنركز عليه: Loopback على R2 → 2.2.2.2/32

من R1 هيبقى فيه مسارين لـ 2.2.2.2:

  • Path 1 (الأفضل): R1 → R2 مباشرة عبر Serial 10.0.0.0/30
  • Path 2 (الأبطأ): R1 → R3 → R2 عبر Serial 11.0.0.0/30 ثم Ethernet 12.0.0.0/24

2. Lab Instructions – Steps

  1. بناء الـ Topology زي ما هو موضح فوق (3 Routers + روابط Serial + Ethernet بين R2 و R3).
  2. ضبط الـ IP Addresses على كل الـ Interfaces حسب الجدول في القسم 3.
  3. تفعيل EIGRP AS 1 على الـ 3 Routers مع الـ Network Statements الصحيحة.
  4. ضبط Bandwidth و Delay (اختياري لكن مفيد عشان تتحكم في الـ Metric وتخلي المسارات Unequal بشكل واضح).
  5. تفعيل Variance على R1 فقط: variance 2.
  6. التحقق من الـ Topology Table و الـ Routing Table إن الـ Pathين ظاهرين.
  7. اختبار الـ Load Balancing بـ traceroute و ping من R1 لـ 2.2.2.2.
ملاحظة مهمة: الـ Variance بيتطبق على الـ Router اللي عايز يعمل Load Balancing (هنا R1). مش لازم يتكتب على كل الـ Routers.

3. Devices Configuration

جدول الـ IP Addressing

Device Interface IP Address Subnet Mask
R1 Serial1/0 10.0.0.1 255.255.255.252
R1 Serial1/1 11.0.0.1 255.255.255.252
R2 Serial1/0 10.0.0.2 255.255.255.252
R2 FastEthernet0/0 12.0.0.2 255.255.255.0
R2 Loopback1 2.2.2.2 255.255.255.255
R3 Serial1/1 11.0.0.2 255.255.255.252
R3 FastEthernet0/0 12.0.0.3 255.255.255.0

R1 Configuration

hostname R1
!
interface Serial1/0
 ip address 10.0.0.1 255.255.255.252
 no shutdown
!
interface Serial1/1
 ip address 11.0.0.1 255.255.255.252
 no shutdown
!
router eigrp 1
 variance 2
 network 10.0.0.0 0.0.0.3
 network 11.0.0.0 0.0.0.3
!
ملاحظة على الـ Network Statement:
الأفضل تستخدم Wildcard Mask الصحيح (0.0.0.3 للـ /30) بدلاً من network 10.0.0.1 0.0.0.0. الاتنين هيعملوا، لكن الطريقة الأولى أنضف.

4. Checks and Expected Outputs

1. التحقق من الـ Neighbors

R1# show ip eigrp neighbors

المتوقع: تشوف R2 و R3 كـ Neighbors.

2. الـ Topology Table (الأهم)

R1# show ip eigrp topology

هنا هتشوف مسارين لـ 2.2.2.2:

  • واحد عليه علامة P (Passive) وهو الـ Successor (أفضل مسار عبر R2).
  • التاني Feasible Successor (عبر R3) لو الـ Feasibility Condition متحققة.
R1# show ip eigrp topology 2.2.2.2

الأمر ده هيعرضلك الـ FD و الـ AD بتاع كل مسار بالتفصيل.

3. الـ Routing Table بعد تفعيل Variance

R1# show ip route eigrp

المتوقع بعد variance 2:

D     2.2.2.2 [90/xxxx] via 10.0.0.2, Serial1/0
               [90/yyyy] via 11.0.0.2, Serial1/1

يعني الـ Route ظاهر مرتين → Load Balancing شغال.

لو المسار التاني مش ظاهر في الـ Routing Table:
• تأكد إن الـ AD بتاع المسار التاني < FD بتاع المسار الأفضل (Feasibility Condition).
• زوّد قيمة الـ Variance (جرب 3 أو 4).
• استخدم show ip eigrp topology all-links عشان تشوف كل المسارات حتى لو مش Feasible.

4. أوامر إضافية مفيدة

R1# show ip eigrp topology all-links
R1# show ip protocols
R1# show interfaces serial1/0
R1# show interfaces serial1/1

5. End-to-End Connectivity Tests

1. اختبار الـ Reachability

R1# ping 2.2.2.2
R1# ping 12.0.0.2
R1# ping 12.0.0.3

2. اختبار الـ Load Balancing (الأهم)

R1# traceroute 2.2.2.2

نفّذ الأمر أكتر من مرة. لو الـ Load Balancing شغال، هتلاقي الـ Path بيتغير بين:

  • R1 → R2 مباشرة
  • R1 → R3 → R2
ملاحظة: EIGRP بيعمل Per-Destination Load Balancing افتراضياً (مش Per-Packet). يعني كل Destination بياخد مسار ثابت، لكن لو عملت traceroute كتير أو استخدمت أدوات تانية هتشوف التوزيع.

3. اختبار إضافي (Advanced)

R1# debug ip packet
! أو
R1# show ip cef 2.2.2.2 detail

هتشوف الـ CEF بيوزع الـ Traffic على الـ Paths الموجودة.

6. Troubleshooting

المشكلة السبب المحتمل الحل
المسار التاني مش ظاهر في Topology Feasibility Condition مش متحققة غيّر Bandwidth/Delay عشان الـ AD يبقى أصغر من الـ FD
المسار ظاهر في Topology بس مش في Routing Table قيمة Variance صغيرة زوّد variance (جرب 2 أو 3 أو 4)
مفيش Neighbor بين R1 و R3 الـ Network Statement ناقص أو Interface Down تحقق من show ip eigrp neighbors و show ip interface brief
الـ Metric متساوي (Equal Cost) الـ Bandwidth والـ Delay افتراضيين متشابهين اضبط Bandwidth مختلف على الـ Serial Interfaces
Load Balancing مش باين في traceroute Per-Destination behavior استخدم مصادر مختلفة أو CEF commands

أوامر Debugging مفيدة:

debug eigrp packets
debug eigrp fsm
show ip eigrp topology all-links
show ip eigrp traffic
نصيحة ذهبية:
لو عايز تتحكم في الـ Metric بشكل دقيق، استخدم الأوامر دي على الـ Interfaces:
bandwidth 64 أو delay 1000 (القيم بالـ Kbps و Tens of microseconds).
ده بيخليك تقدر تخلّي مسار أبطأ أو أسرع بسهولة.

🧠 ملخص سريع

  • Variance بيسمح بـ Unequal Cost Load Balancing.
  • لازم يتحقق شرطين: Feasibility Condition + Variance × Best Metric.
  • الـ Variance بيتكتب على الـ Router اللي عايز يعمل Load Balancing (R1 هنا).
  • التحقق الأساسي من show ip eigrp topology و show ip route.
اللاب ده جزء من سلسلة EIGRP – لو عايز اللاب الجاي (مثلاً EIGRP Stub أو Authentication أو Named Mode) قولي وأجهزهولك بنفس الأسلوب.
