# **Lab 8.2 – DHCP Relay (IP Helper Address)**

## **1. Lab Overview**

**Objective:** Configure DHCP Relay using `ip helper-address` to allow clients in a remote LAN to obtain IP addresses from a centralized DHCP Server located in a different subnet.

**Scenario:**

In this lab we have:

- **Router:** Connects the Client LAN to the DHCP Server network.
    
- **DHCP Server:** Provides IP addresses to clients using DHCP.
    
- **Client:** Located in a different subnet from the DHCP Server.


**IP Addressing Table**

|Device|Interface|IP Address|
|---|---|---|
|Router|Fa0/0|10.0.0.1/24|
|Router|Fa1/0|192.168.1.1/24|
|DHCP Server|Fa0/0|10.0.0.2/24|
|Client|NIC|DHCP|

**DHCP Pool Information**

|Parameter|Value|
|---|---|
|Pool Name|LAN1|
|Network|192.168.1.0/24|
|Default Gateway|192.168.1.1|
|DNS Server|8.8.8.8|

**How DHCP Relay Works**

Normally DHCP Discover is a broadcast message and routers do not forward broadcasts between different networks.

Here comes the role of `ip helper-address`.

1. Client sends DHCP Discover as a broadcast.
    
2. Router receives the broadcast on Fa1/0.
    
3. `ip helper-address` forwards the DHCP request as a unicast to 10.0.0.2.
    
4. DHCP Server receives the request and selects the appropriate DHCP Pool.
    
5. DHCP Server sends the DHCP Offer back to the Router.
    
6. Router forwards the Offer to the Client.


## **2. Lab Instructions – Steps**

### **Step 1 – Configure Router Interfaces**

Configure the two Router interfaces:

- Fa0/0 connects to the DHCP Server network.
    
- Fa1/0 connects to the Client LAN.
    

```
Router(config)# interface FastEthernet0/0
Router(config-if)# ip address 10.0.0.1 255.255.255.0
Router(config-if)# no shutdown

Router(config)# interface FastEthernet1/0
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# no shutdown
```

### **Step 2 – Configure DHCP Relay**

Configure the `ip helper-address` command on the interface connected to the Client LAN.

```
Router(config)# interface FastEthernet1/0
Router(config-if)# ip helper-address 10.0.0.2
```

**Important:** We configure `ip helper-address` on the interface that receives the DHCP broadcast from clients.

Not on the interface connected to the DHCP Server.

### **Step 3 – Configure DHCP Server**

Configure the DHCP Pool to provide IP addresses for the remote LAN.

```
DHCP(config)# ip dhcp excluded-address 192.168.1.1

DHCP(config)# ip dhcp pool LAN1
DHCP(dhcp-config)# network 192.168.1.0 255.255.255.0
DHCP(dhcp-config)# default-router 192.168.1.1
DHCP(dhcp-config)# dns-server 8.8.8.8
```


### **Step 4 – Configure Return Routing**

The DHCP Server needs a route to reach the Client LAN.

```
DHCP(config)# ip route 192.168.1.0 255.255.255.0 10.0.0.1
```

This tells the DHCP Server to forward packets destined for `192.168.1.0/24` through the Router at `10.0.0.1`.

### **Step 5 – Configure Client**

Configure the Client PC to obtain its IP address automatically using DHCP.

On a Windows client:

```
VPC> ip dhcp
```


## **4. Checks and Expected Outputs**

### **Router Checks**

**Check 1 – Verify Interfaces**

```
Router# show ip interface brief
```

Expected Output:

```
Interface          IP-Address      Status     Protocol
FastEthernet0/0    10.0.0.1        up         up
FastEthernet1/0    192.168.1.1     up         up
```

**Check 2 – Verify IP Helper Address**

```
Router# show running-config interface FastEthernet1/0
```

Expected Output:

```
interface FastEthernet1/0
 description CLIENT-LAN
 ip address 192.168.1.1 255.255.255.0
 ip helper-address 10.0.0.2
```

### **DHCP Server Checks**

**Check 3 – Verify DHCP Pool**

```
DHCP# show ip dhcp pool
```

Expected Output (key fields):

```
Pool LAN1 :
 Utilization mark (high/low)    : 100 / 0
 Subnet size (first/next)       : 0 / 0
 Total addresses                : 254
 Leased addresses               : 0
 Pending event                  : none
 1 subnet is currently in the pool :
 Current index        IP address range
 192.168.1.1          192.168.1.1 - 192.168.1.254
```

The exact output and utilization fields may vary by IOS version.

**Check 4 – Verify DHCP Bindings**

```
DHCP# show ip dhcp binding
```

Before a client requests an IP address:

```
Bindings from all pools not associated with VRF:
```

After a successful DHCP request (illustrative):

```
IP address       Client-ID/              Lease expiration        Type
                 Hardware address

```

The actual assigned IP and Client-ID depend on the client.

## **5. End-to-End Connectivity Tests**

The purpose of this section is to verify that the DHCP Relay works correctly from the Client side.

### **Test 1 – Obtain IP Address Automatically**

On the Client PC:

```
VPC> ip dhcp
```

Expected Output:

```
IPv4 Address. . . . . . . . . : 192.168.1.2
Subnet Mask . . . . . . . . . : 255.255.255.0
Default Gateway . . . . . . . : 192.168.1.1
DNS Servers . . . . . . . . . : 8.8.8.8
```

Expected Result: Success

The Client receives its IP configuration from the remote DHCP Server.

![](Pasted%20image%2020261122233202.png)

### **Test 2 – Verify Default Gateway**

```
ping 192.168.1.1
```

Expected Output:

```
Reply from 192.168.1.1: bytes=32 time<escape><</escape>1ms TTL=255
```

Expected Result: Success

### **Test 3 – Verify DHCP Server Connectivity**

```
ping 10.0.0.2
```

Expected Output:

```
Reply from 10.0.0.2: bytes=32 time<escape><</escape>1ms TTL=254
```

Expected Result: Success

This verifies that the Client can communicate with the DHCP Server through the Router.

## **6. Troubleshooting**

### **Useful Troubleshooting Commands**

**On Router:**

```
show ip interface brief
show running-config interface FastEthernet1/0
show ip route
show ip interface FastEthernet1/0
```

**On DHCP Server:**

```
show ip dhcp pool
show ip dhcp binding
show ip dhcp server statistics
show ip route
show running-config
```

**Debug Commands**

On Router:

```
debug ip dhcp server packet
```

On DHCP Server:

```
debug ip dhcp server packet
```

Use `undebug all` to stop debugging.
