# **Lab 8.2 – EIGRP Unequal-Cost Load Balancing**

## **1. Lab Overview**

**Objective:** Configure EIGRP Unequal-Cost Load Balancing using the `variance` command to allow traffic to use multiple paths with different metric values.


**IP Addressing Table**

|Device|Interface|IP Address|Network|
|---|---|---|---|
|R1|S1/0|10.0.0.1/30|10.0.0.0/30|
|R2|S1/0|10.0.0.2/30|10.0.0.0/30|
|R1|S1/1|11.0.0.1/30|11.0.0.0/30|
|R3|S1/1|11.0.0.2/30|11.0.0.0/30|
|R2|Fa0/0|12.0.0.2/24|12.0.0.0/24|
|R3|Fa0/0|12.0.0.3/24|12.0.0.0/24|
|R2|Lo1|2.2.2.2/32|2.2.2.2/32|


## **2. Lab Instructions – Steps**

### **Step 1 – Configure IP Addressing**

Configure the IP addresses on all router interfaces according to the IP Addressing Table.

Make sure all interfaces are operational.

### **Step 2 – Configure EIGRP**

Configure EIGRP using Autonomous System number 1.

On R1:

```
router eigrp 1
 network 10.0.0.1 0.0.0.0
 network 11.0.0.1 0.0.0.0
```

On R2:

```
router eigrp 1
 network 2.2.2.2 0.0.0.0
 network 10.0.0.2 0.0.0.0
 network 12.0.0.2 0.0.0.0
```

On R3:

```
router eigrp 1
 network 11.0.0.2 0.0.0.0
 network 12.0.0.3 0.0.0.0
```

### **Step 3 – Configure Variance**

On R1 configure:

```
router eigrp 1
 variance 2
```

This enables EIGRP to consider qualifying paths with a metric up to two times the best path metric.

### **Step 4 – Verify EIGRP Neighbors**

Run:

```
show ip eigrp neighbors
```

Verify that R1 has established EIGRP neighbor relationships with R2 and R3.

### **Step 5 – Verify EIGRP Topology**

Run:

```
show ip eigrp topology
```

Check the available paths and their metrics.

### **Step 6 – Verify Unequal-Cost Load Balancing**

On R1:

```
show ip route eigrp
```

Check whether multiple paths are installed for the destination network.

## **4. Checks and Expected Outputs**

### **4.1 Check EIGRP Neighbors**

On R1:

```
show ip eigrp neighbors
```

Expected output:

```
H   Address       Interface
0   10.0.0.2      Se1/0
1   11.0.0.2      Se1/1
```

Both R2 and R3 should appear as EIGRP neighbors.


### **4.2 Check Routing Table – Before Changing Variance**

On R1:

```
show ip route | begin Gateway
```

Expected output:

```
R1#sh ip route | begin Gateway
Gateway of last resort is not set

      2.0.0.0/32 is subnetted, 1 subnets
D        2.2.2.2 [90/2297856] via 10.0.0.2, 00:04:48, Serial1/0
      10.0.0.0/8 is variably subnetted, 2 subnets, 2 masks
C        10.0.0.0/30 is directly connected, Serial1/0
L        10.0.0.1/32 is directly connected, Serial1/0
      11.0.0.0/8 is variably subnetted, 2 subnets, 2 masks
C        11.0.0.0/30 is directly connected, Serial1/1
L        11.0.0.1/32 is directly connected, Serial1/1
      12.0.0.0/24 is subnetted, 1 subnets
D        12.0.0.0 [90/2172416] via 11.0.0.2, 00:04:48, Serial1/1
                  [90/2172416] via 10.0.0.2, 00:04:48, Serial1/0
R1#
```

**Analysis:**

- Destination `2.2.2.2/32` uses one path through R2.
    
- Destination `12.0.0.0/24` already has two equal-cost paths.
    
- Equal-cost load balancing is already working for `12.0.0.0/24`.
    
- The goal is to enable the additional unequal-cost path for `2.2.2.2/32`.
    



### **4.3 Check EIGRP Topology – Before Changing Variance**

Before change

Initially the variance value is not configured or is left at its default value of 1.

On R1:

```
show ip eigrp topology
```

Expected output:

```
R1#sh ip eigrp topology
EIGRP-IPv4 Topology Table for AS(1)/ID(11.0.0.1)
Codes: P - Passive, A - Active, U - Update, Q - Query, R - Reply,
       r - reply Status, s - sia Status

P 12.0.0.0/24, 2 successors, FD is 2172416
        via 10.0.0.2 (2172416/28160), Serial1/0
        via 11.0.0.2 (2172416/28160), Serial1/1
P 10.0.0.0/30, 1 successors, FD is 2169856
        via Connected, Serial1/0
P 2.2.2.2/32, 1 successors, FD is 2297856
        via 10.0.0.2 (2297856/128256), Serial1/0
        via 11.0.0.2 (2300416/156160), Serial1/1
P 11.0.0.0/30, 1 successors, FD is 2169856
        via Connected, Serial1/1

R1#
```

**Analysis:**

For destination `2.2.2.2/32`:

|Path|Next Hop|Metric|
|---|---|---|
|Primary Path|10.0.0.2|2297856|
|Alternative Path|11.0.0.2|2300416|

The first path has the lowest metric and is selected as the Successor.

The alternative path is not installed because the default variance is 1.

### **4.4 Configure EIGRP Variance**

On R1:

```
R1# configure terminal
R1(config)# router eigrp 1
R1(config-router)# variance 2
R1(config-router)# end
```

This allows EIGRP to install qualifying paths with metrics up to two times the best path metric.
