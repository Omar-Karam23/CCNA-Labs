# OSPF Multi-Area Lab

## 1. Lab Overview

This lab demonstrates basic OSPF configuration using two Cisco routers (R1 and R2).
Both routers are connected through FastEthernet0/0 and use OSPF Process ID 1.

The lab focuses on:

- Configuring OSPF directly on interfaces.
    
- Assigning interfaces to different OSPF Areas.
    
- Establishing OSPF Neighbor Adjacency.
    
- Understanding OSPF Area 0 and Area 20.
    
- Verifying OSPF neighbors and the Link-State Database (LSDB).
    
- Troubleshooting OSPF routing and connectivity issues.
    
---

## 2. Lab Instructions – Steps

### Step 1: Configure IP Addressing

Configure the Loopback and FastEthernet interfaces on both routers according to the IP Addressing Table.

### Step 2: Enable OSPF on R1

Enable OSPF Process 1 on Loopback1 and FastEthernet0/0.

Both interfaces belong to Area 0.

### Step 3: Enable OSPF on R2

Enable OSPF Process 1 on FastEthernet0/0 in Area 0.

Configure Loopback2 in Area 20.

### Step 4: Establish OSPF Neighbor Adjacency

Verify that R1 and R2 successfully establish an OSPF neighbor relationship through FastEthernet0/0.

### Step 5: Verify OSPF Operation

Check the following:

- OSPF Neighbor Table.
    
- OSPF Interface Information.
    
- OSPF Database.
    
- Routing Table.
    

### Step 6: Test Connectivity

Perform connectivity tests between the directly connected interfaces and the Loopback interfaces.

## 3. Devices Configuration

### R1 Configuration

```
hostname R1
!
interface Loopback1
 ip address 1.1.1.1 255.255.255.255
 ip ospf 1 area 0
!
interface FastEthernet0/0
 ip address 10.0.0.1 255.255.255.0
 ip ospf 1 area 0
 no sh
```

### R2 Configuration

```
hostname R2
!
interface Loopback2
 ip address 2.2.2.2 255.255.255.255
 ip ospf 1 area 20
!
interface FastEthernet0/0
 ip address 10.0.0.2 255.255.255.0
 ip ospf 1 area 0
 no sh
```

## 4. Checks and Expected Outputs

### 4.1 Verify OSPF Neighbors

Run the following command on both routers:

```
show ip ospf neighbor
```

Expected result on R1:

```
Neighbor ID     Pri   State      Dead Time   Address      Interface
2.2.2.2           1   FULL/DR    00:00:3x    10.0.0.2     FastEthernet0/0
```

Expected result on R2:

```
Neighbor ID     Pri   State      Dead Time   Address      Interface
1.1.1.1           1   FULL/BDR   00:00:3x    10.0.0.1     FastEthernet0/0
```

### 4.3 Verify OSPF Database

```
show ip ospf database
```

This command displays the Link-State Database (LSDB).

Check the available LSA types, especially:

- Type 1 – Router LSA.
    
- Type 2 – Network LSA.

## 6. Troubleshooting

Use the following commands to identify and troubleshoot common OSPF issues.

| Command                        | Purpose                                              |
| ------------------------------ | ---------------------------------------------------- |
| `show ip ospf neighbor`        | Verify OSPF neighbor relationships.                  |
| `show ip ospf interface brief` | Verify OSPF-enabled interfaces and Area assignments. |
| `show ip ospf database`        | Inspect the OSPF Link-State Database.                |
| `show ip route ospf`           | Display routes learned through OSPF.                 |
| `show ip protocols ospf`       | Verify OSPF process information.                     |
| `show ip interface brief`      | Check interface status and IP addressing.            |
| `debug ip ospf hello`          | to detect error                                      |
---------------------------- | ---------------------------------------------------- |
