# **OSPF Default Route Origination**

## **1. Lab Overview**

### **Objective**

The objective of this lab is to understand how to advertise a default route into an OSPF routing domain using the `default-information originate` command.

R1 acts as the gateway router and is responsible for injecting the default route into the OSPF domain. R2 and R3 learn this default route dynamically through OSPF.

## **2. Lab Instructions – Steps**

### **Step 1: Configure IP Addressing**

Configure the IP addresses on all router interfaces according to the addressing table.

### **Network Addressing**

| Device | Interface | IP Address  | Subnet Mask     |
| ------ | --------- | ----------- | --------------- |
| R1     | Fa0/0     | 10.0.0.1    | 255.255.255.252 |
| R1     | Fa1/0     | 11.0.0.1    | 255.255.255.252 |
| R1     | Fa2/0     | 192.168.1.1 | 255.255.255.0   |
| R2     | Fa0/0     | 10.0.0.2    | 255.255.255.252 |
| R2     | Fa1/0     | 12.0.0.2    | 255.255.255.252 |
| R2     | Loopback1 | 2.2.2.2     | 255.255.255.255 |
| R3     | Fa0/0     | 12.0.0.1    | 255.255.255.252 |
| R3     | Fa1/0     | 11.0.0.2    | 255.255.255.252 |

### **Step 2: Configure OSPF**

Enable OSPF Process ID 1 on all routers.

Configure all participating interfaces in Area 0.

### **Step 3: Configure the Static Default Route on R1**

Configure a static default route pointing toward FastEthernet2/0.

This provides R1 with a default route that can be advertised into the OSPF domain.

```
R1(config)# ip route 0.0.0.0 0.0.0.0 FastEthernet2/0
```

### **Step 4: Advertise the Default Route into OSPF**

Under the OSPF routing process on R1 configure:

```
R1(config)# router ospf 1
R1(config-router)# default-information originate
```

**Important:** By default `default-information originate` advertises the default route only when a default route already exists in the routing table.

The `always` keyword can force OSPF to advertise the default route even when no default route exists in the routing table.

### **Step 5: Verify Default Route Advertisement**

On R2 and R3 verify that the default route has been learned through OSPF.

```
show ip route
show ip route ospf
```

The expected result is an OSPF External Type 2 default route.

## **3. Devices Configuration**

The following configurations represent the essential commands required to implement the lab.

### **R1 – Default Route Originator**

**Global Configuration Mode**

```
hostname R1

interface FastEthernet0/0
 ip address 10.0.0.1 255.255.255.252
 ip ospf 1 area 0
 no shutdown

interface FastEthernet1/0
 ip address 11.0.0.1 255.255.255.252
 ip ospf 1 area 0
 no shutdown

interface FastEthernet2/0
 ip address 192.168.1.1 255.255.255.0
 no shutdown

ip route 0.0.0.0 0.0.0.0 FastEthernet2/0

router ospf 1
 default-information originate
```

### **R2 – OSPF Internal Router**

**Global Configuration Mode**

```
hostname R2

interface Loopback1
 ip address 2.2.2.2 255.255.255.255
 ip ospf 1 area 0

interface FastEthernet0/0
 ip address 10.0.0.2 255.255.255.252
 ip ospf 1 area 0
 no shutdown

interface FastEthernet1/0
 ip address 12.0.0.2 255.255.255.252
 ip ospf 1 area 0
 no shutdown

```

### **R3 – OSPF Internal Router**

**Global Configuration Mode**

```
hostname R3

interface FastEthernet0/0
 ip address 12.0.0.1 255.255.255.252
 ip ospf 1 area 0
 no shutdown

interface FastEthernet1/0
 ip address 11.0.0.2 255.255.255.252
 ip ospf 1 area 0
 no shutdown

```

## **4. Checks and Expected Outputs**

### **4.1 Verify Interface Status**

Run on all routers:

```
show ip interface brief
```

**Expected Result:**

All configured physical interfaces should show:

```
Status    Protocol
up        up
```

### **4.2 Verify OSPF Neighbor Adjacencies**

```
show ip ospf neighbor
```

**R1 Expected Output:**

```
Neighbor ID     State      Address      Interface
2.2.2.2         FULL/...   10.0.0.2     FastEthernet0/0
< R3 Router ID > FULL/...  11.0.0.2     FastEthernet1/0
```


### **4.3 Verify the Default Route on R1**

```
show ip route static
```

**Expected Output:**

```
S*    0.0.0.0/0 is directly connected, FastEthernet2/0
```

This confirms that R1 has a static default route in its routing table.

### **4.4 Verify OSPF Default Route Advertisement**

Run on R2 and R3:

```
show ip route ospf
```

**Expected Output:**

```
O*E2  0.0.0.0/0 [110/1] via 10.0.0.1, FastEthernet0/0
```

On R3 the next hop should be R1 through FastEthernet1/0:

```
O*E2  0.0.0.0/0 [110/1] via 11.0.0.1, FastEthernet1/0
```

Expected Result

Both R2 and R3 should learn the default route as an OSPF External Type 2 route.

### **4.5 Verify OSPF Database**

```
show ip ospf database external
```

**Expected Result:**

The OSPF database should contain an External LSA (Type 5) advertising:

```
Link State ID: 0.0.0.0
Advertising Router: R1 Router ID
Network Mask: 0.0.0.0
```

This confirms that R1 has originated the default route into the OSPF domain.

## **5. End-to-End Connectivity Tests**

### **Test 1: Verify Loopback Connectivity**

From R1:

```
R1# ping 2.2.2.2
```

Expected: Successful replies from R2 Loopback1.

### **Test 2: Verify Default Route Connectivity from R2**

```
R2# ping 192.168.1.1
```

Expected: Successful replies through the default route learned from R1.

### **Test 3: Verify Default Route Connectivity from R3**

```
R3# ping 192.168.1.1
```

Expected: Successful replies through the default route learned from R1.
